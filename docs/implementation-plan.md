# 자동 얼굴 분석·파츠 분리 구현 계획

작성일: 2026-11-15. 기준 커밋: `4a001c8`.

## 목표와 현재 상태

이미지를 넣으면 얼굴 위치와 눈·입 기준점을 찾고, 실제 이미지 경계를 따라 파츠 초안을 제안한다. 사용자는 틀린 영역만 수정한 뒤 Cubism 후반 작업용 PSD와 리깅 참고 자료를 내보낸다. Rust + Tauri v2, `ort`, `delaunator`, `glam`을 유지한다. 주차 대신 기능 의존성과 완료 조건으로 진행한다.

현재 구현과 앞으로 구현할 기능을 구분한다.

| 영역        | 현재                        | 다음 구현                                            |
| ----------- | --------------------------- | ---------------------------------------------------- |
| 얼굴 위치   | 고정 비율 또는 사용자 박스  | 일러스트용 얼굴 검출, 후보 선택                      |
| 랜드마크    | 비율로 만든 5점과 수동 이동 | 모델 출력, 점별 점수, 수동 수정 보존                 |
| 배경        | U2Net/U2NetP 또는 색상 제거 | 기존 경로 재사용, 모델 관리 통합                     |
| 세부 파츠   | 랜드마크 주변 기하 분할     | 이미지 기반 자동 다층 분할(다발 머리 포함)·클릭 보정 |
| 가림 보완   | 12px 단순 인접색 확장       | 경계 침식 보간·넓은 패딩, 선택적 인페인팅 모델 검토  |
| 메쉬·변형   | Delaunay와 규칙 기반 변형   | 개선된 윤곽·랜드마크 반영, 다중 머리 흔들림·품질 검사|
| Cubism 인계 | PSD와 자체 JSON             | 계층형 PSD 구조 정리·실제 Editor 가져오기 검증       |

고정 좌표는 자동 인식 결과로 표시하지 않는다. 모델 미설치·검출 실패 시 수동 모드라는 사실을 알린다. 이 문서는 구현 예정 사항이며, 모델 채택과 수치 목표는 아직 검증되지 않았다.

## 사용 흐름

1. PNG/JPEG를 드래그해 넣는다. 원본을 보관하고 작업 해상도로 변환한다.
2. 모델이 준비되어 있으면 얼굴을 분석한다. 여러 얼굴이 있으면 대상을 선택한다. 모델이 없으면 설치/로컬 연결 또는 수동 지정을 선택한다.
3. 눈·입·턱 기준점과 파츠 마스크를 겹쳐 보여준다. 확인이 필요한 항목부터 안내한다.
4. 점 이동, 파츠별 포함/제외 클릭, 브러시로 보정한다. 수정한 파츠만 다시 계산할 수 있다.
5. 파츠 확인 후 PSD를 내보낸다. 모션·메쉬 미리보기와 모델 설정은 별도 탭/고급 설정으로 둔다.

기본 화면의 주요 행동은 `이미지 넣기 → 파츠 확인·수정 → PSD 내보내기`로 제한한다. 작업 중인 수동 수정은 자동 분석이나 재생성으로 덮어쓰지 않는다. 덮어쓸 대상은 적용 전에 미리 보여준다. 화면 표현은 `DESIGN.md`를 따른다.

## 모델 선택

| 역할           | 우선 검증 후보                                          | 채택 전 확인                                                      |
| -------------- | ------------------------------------------------------- | ----------------------------------------------------------------- |
| 얼굴 검출      | hysts/anime-face-detector의 얼굴 검출 모델              | 원화별 검출, ONNX 연산 지원, NMS 일치                             |
| 랜드마크       | 같은 프로젝트의 HRNetV2 28점                            | crop/affine/heatmap 후처리 재현, 점 의미, Rust 좌표 복원          |
| 배경           | 기존 U2NetP                                             | 기존 결과 회귀, 피부·머리 경계 손실                               |
| 파츠 경계·보정 | MobileSAM의 경량 이미지 인코더와 프롬프트/마스크 디코더 | 인코더와 디코더 모두 ONNX로 실행 가능한지, 원화의 작은 눈·입 품질 |

hysts 프로젝트는 정면에 가까운 애니메이션 얼굴 검출과 28점 추정을 제공한다. 배포된 PyTorch 모델을 그대로 `ort`에서 읽을 수 있다고 가정하지 않는다. 먼저 변환과 원본 대비 결과 일치를 검증한다. [공식 저장소](https://github.com/hysts/anime-face-detector)

MobileSAM은 ONNX export 예제를 제공하지만, 공식 스크립트의 export 범위와 이미지 인코더 경로를 따로 확인한다. 디코더 파일 하나만 확보한 상태를 전체 파이프라인 준비 완료로 처리하지 않는다. [공식 저장소](https://github.com/ChaoningZhang/MobileSAM), [export 스크립트](https://github.com/ChaoningZhang/MobileSAM/blob/master/scripts/export_onnx_model.py)

프롬프트 기반 분할 모델이 파츠 이름이나 앞머리/뒤머리 관계까지 자동 판별한다고 가정하지 않는다. 랜드마크와 위치 규칙으로 이름이 붙은 후보를 제안하고, 의미를 확정할 수 없는 것은 사용자 확인 대상으로 남긴다. 작은 눈·입이나 앞/뒤 머리 구분이 목표 품질에 못 미치면 전용 파츠 모델 학습을 후속 작업으로 분리하고, 해당 범주를 자동 분리 완료로 표시하지 않는다.

Python은 모델 export·검증·평가 도구에만 사용한다. 사용자 앱의 실행 경로는 Rust + ONNX Runtime으로 유지한다. 변환이 막힌 후보는 앱에 Python 의존성을 추가해 우회하기 전에 대체 모델을 평가한다. 코드 라이선스와 가중치 배포 조건은 별도로 기록한다.

## 구현 순서와 완료 조건

### 1. 평가 자료와 모델 계약 확정

- 개발용 원화 10장, 결과 판정용 별도 정면 원화 20장, 얼굴 없는 이미지 10장, 다중 얼굴 예외 3장을 마련한다. 사용 가능한 자료만 평가에 쓴다. 로컬 `sutteang/`의 2장은 초기 재현 자료로 사용하되 전체 품질 근거로 삼지 않는다.
- 얼굴 박스, 눈 중심·입 중심·턱, 보이는 파츠 마스크, 가림/미해당 여부를 주석 처리한다. 평가용 20장은 임계값 조정에 사용하지 않는다.
- `tools/model-export/`에 버전이 고정된 export 환경과 원본/ONNX 비교 스크립트를 둔다. 검출·랜드마크를 먼저 검증하고, 파츠 모델은 그다음 검증한다.
- `models/manifest.json`에 역할, 모델 버전, upstream revision, 다운로드 위치, SHA-256, 입력 shape·정규화·색상 순서, 출력, 후처리 버전, 라이선스를 기록한다.
- `tools/evaluation/`에서 케이스별 오버레이, JSON 지표, 처리 시간·메모리 보고서를 생성한다. 원화와 모델 가중치는 기본 소스 커밋에 포함하지 않는다.

완료 조건: 얼굴/랜드마크 후보를 CPU ONNX Runtime에서 실행하고 원본 구현과 비교할 수 있어야 한다. 출력은 finite여야 하며, 검출 박스 차이·랜드마크 좌표 차이·마스크 차이를 고정 입력에서 수치로 보고한다. 얼굴/랜드마크 좌표 차이 목표는 모델 입력 기준 1px 이하로 두고, 실제 모델의 후처리 특성에 따른 허용 오차를 명시한다. 이 조건을 통과하기 전 앱에 자동 검출 완료 상태를 노출하지 않는다.

### 2. 얼굴 검출과 랜드마크 연결

- `src-tauri/src/analysis/`에 `detector.rs`, `landmarks.rs`, `transforms.rs`, `models.rs`를 추가한다. 기존 배경 추론 경로와 역할을 나눈다.
- 입력 색상 순서, resize/letterbox, 얼굴 crop과 회전/affine 변환을 명시적으로 관리한다. `glam` 행렬과 역행렬로 모델 좌표 → 작업 좌표 → 원본 좌표를 복원한다.
- 얼굴 후보마다 박스·검출 점수·모델 랜드마크·점별 점수를 반환한다. 사람이 편집한 점에는 출처 `manual`을 저장한다. 모델의 원시 점수를 검증된 확률로 표현하지 않는다.
- 28점 원본 결과는 보존하고 기존 5점 인터페이스에는 별도 어댑터를 둔다. 얼굴 피부 상단처럼 모델이 직접 예측하지 않는 점은 추정값으로 표시한다. 캐릭터 좌우와 화면 좌우 매핑을 고정한다.
- `analyze_face` 명령을 `lib.rs`에 등록하고 `src/native.ts`에서 연결한다. 검출 실패, 여러 얼굴, 작은 얼굴, 가려진 눈을 서로 구분한다.
- `src/App.tsx`에서 분석 결과를 표시하고 실패 시 얼굴 박스 수동 지정을 제공한다. 수동 수정이 있는 프로젝트를 재분석할 때 기존 점을 자동 교체하지 않는다.

완료 조건: 얼굴 위치·크기·여백을 바꾼 동일 그림에서도 점이 얼굴을 따라가야 한다. 회전/크롭/원본 좌표 왕복, 좌우 매핑, 얼굴 없음, 다중 얼굴을 검증한다. 검출 실패를 고정 좌표 성공으로 대체하지 않는다.

### 3. 이미지 기반 파츠 제안과 클릭 보정 (다층 머리카락 포함)

- `analysis/segmentation.rs`, `parts.rs`에서 얼굴 박스·랜드마크(눈·입·턱·얼굴 상단)를 기준으로 파츠별 박스/포함점/제외점을 자동 생성한다. 작은 눈·입은 얼굴 확대 crop으로 분석하고 작업 좌표에 복원한다.
- 사용자가 얼굴 영역과 기준점(눈·입·턱·얼굴 상단)을 확정하면, 기본 18개 파츠에 더해 **머리카락을 앞머리·좌/우 옆머리·뒷머리로 1차 자동 분리**한다.
  - 얼굴 상단·눈·턱선을 기준으로 `hair_front`(이마/눈 위 앞머리), `hair_side_L` / `hair_side_R`(관자놀이~볼/턱 옆으로 내려오는 옆머리), `hair_back`(얼굴 외곽·턱선 뒤/아래 뒷머리) 프롬프트와 연결 성분을 조합해 초기 다발 후보를 제안한다.
  - 같은 영역 안에서 여러 가닥(예: `앞머리 1, 2`, `옆머리 1, 2, 3`, `뒷머리 1, 2`)이 겹치는 캐릭터는 고정 18개 `IDS` 제약을 풀어 가변 파츠 목록으로 수용하고, 사용자가 `+ 머리카락 파츠` 추가 후 가닥 위를 1~2회 클릭하면 MobileSAM 디코더로 해당 가닥만 추출하면서 기존 상위 머리 마스크에서 해당 픽셀을 차감(옵션)할 수 있게 한다.
- 배경 알파와 마스크 교집합, 연결 성분, 경계 누출, 좌우 뒤바뀜, 빈 영역을 검사한다. 마스크 품질이 낮으면 브러시 또는 포함/제외 클릭으로 보정한다.
- 이미지 임베딩은 이미지·모델·전처리 버전별로 캐시하고, 클릭을 추가할 때는 디코더만 재실행한다. 한 번에 여러 마스크를 제안하면 사용자가 후보를 고를 수 있게 한다.
- 첫 완료 대상은 얼굴, 목, 몸통, 양쪽 눈 전체, 양쪽 눈썹, 입 전체와 다층 머리 영역(`hair_front*`, `hair_side*`, `hair_back*`)이다. 의미·겹침 순서를 확정할 수 없는 가닥은 사용자 확인 대상으로 남긴다.
- 세부 분리가 검증되기 전에는 눈 전체/입 전체 같은 상위 파츠를 별도 ID로 추가하고, 겹치는 세부 파츠를 함께 활성화하지 않는다. 흰자·홍채·눈꺼풀·입술을 임의로 잘라 18개 성공으로 집계하지 않는다.
- 파츠별 출처를 `model`, `prompted`, `geometry`, `manual`로 저장하고, 역할(`partRole`: `hair_front`/`hair_side`/`hair_back` 등)과 상태(`draft`, `approved`, `missing`)를 분리한다. 신뢰하기 어려운 후보에는 확인 이유를 표시한다.

완료 조건: 기준점 주변의 도형이 아니라 원화의 경계를 따라 마스크가 달라져야 한다. 같은 위치의 서로 다른 머리/눈 형태를 테스트하고, 머리카락 가닥을 클릭해 별도 레이어로 분리·차감할 때 다른 파츠의 수동 수정과 승인 상태가 유지되어야 한다.

### 4. 가림과 레이어 합성 처리 (움직임 공백 보완)

- `Part.mask` 하나에 보이는 영역, 복원 영역, 출력 알파를 모두 넣던 구조를 나눈다. `visibleMask`, `fillMask`, 출력 마스크/텍스처와 합성 순서(`compositeOrder`)를 저장한다.
- 보이는 픽셀의 분리와 숨겨진 영역의 복원을 별개 작업으로 처리한다. 앞머리/옆머리가 흔들리거나 고개가 돌아갈 때 생기는 공백을 줄이기 위해 2단계 보완을 적용한다:
  1. **비생성형 경계 보완 개선(기본)**: 기존 `12px` 단순 경계 복사 시 머리색/선화 그림자가 피부로 번지는 문제를 막기 위해 **마스크 외곽 2~3px 침식 후 내부 색 보간 확장**을 사용한다. 또한 `face`/`neck`/`hair_back`처럼 상위 레이어에 넓게 가려지는 파츠는 가린 레이어의 폭과 얼굴 윤곽·좌우 대칭을 참고해 고정 12px 이상으로 패딩 범위를 확장한다.
  2. **경량 인페인팅 모델(선택 검토)**: 볼 절반이나 뒷머리 뒤 배경처럼 넓은 가림 영역을 메워야 할 때를 대비해 `ModelRole::Inpainter`(예: LaMa ONNX 등) 추가 여부를 별도 모델 평가로 검증한다. 기본 자동 분석의 선행 조건으로 묶지 않으며, 선화 복원이 필요한 정밀 보완은 기존 외부 PNG 교체 경로를 유지한다.
- 앞머리 아래 피부처럼 최종 레이어가 겹치는 구조를 허용한다. 기존의 모든 파츠 마스크 합이 원본 알파와 정확히 같아야 한다는 규칙은 `visibleMask` 분리에만 적용하고, 보완된 출력 레이어에는 적용하지 않는다.

완료 조건: 원본 합성 비교에서 픽셀 중복·빈틈을 확인할 수 있고, 복원한 영역(`fillMask`)을 별도 오버레이로 볼 수 있어야 한다. 경계 침식 보완 적용 시 머리카락 색이 피부 확장 영역으로 번지지 않아야 하며, 가림으로 존재 여부를 확인할 수 없는 파츠를 `missing`으로 자동 확정하지 않는다.

### 5. 메쉬·리깅 초안과 저장 형식 정리

- 개선된 파츠 외곽과 눈·입 윤곽을 메쉬 점 배치에 반영한다. 기존 `delaunator`를 유지하며 구멍 가로지름, 긴 삼각형, 뒤집힘을 검사한다.
- 새 랜드마크를 변형 피벗에 연결하고 눈/입 전체와 세부 파츠의 변형 규칙을 구분한다. 다중 머리카락 레이어(`hair_front_*`, `hair_side_*`, `hair_back_*`)는 ID 문자열 접두사(`hair`)에만 의존하지 않고 파츠 역할과 흔들림 진폭·위상 오프셋을 분리해 앞·옆·뒷머리가 서로 다르게 흔들리도록 한다. Rust(`core.rs`)와 TypeScript(`engine.ts`)의 변형 수식 일치를 유지한다.
- 미리보기 격자와 내보내기 메쉬가 다른 현재 구조는 동일 토폴로지 사용을 우선 검토하고, 경계 텍스처 누락을 회귀 검사한다.
- 프로젝트 schema v2에 분석 결과, 모델별 hash, 좌표 변환, 파츠 출처·역할, 수동 잠금, 보완 마스크, 계층/합성 순서를 저장한다. schema v1 읽기와 마이그레이션 테스트를 먼저 추가한다.
- 모델 경로와 임베딩은 프로젝트 필수 데이터로 만들지 않는다. 모델이 없는 PC에서도 저장된 결과를 열고 수정·내보낼 수 있게 한다.
- PSD/인계 JSON에 후보·승인·복원 범위와 다층 레이어 순서(필요 시 그룹 폴더 구조)를 반영한다. 자체 JSON이 Cubism 메쉬/키를 직접 생성한다고 표시하지 않는다.

완료 조건: 기존 프로젝트를 열 수 있고 새 프로젝트의 저장·재열기가 분석 결과와 수동 수정을 유지한다. 슬라이더 극값에서 메쉬 뒤집힘이나 큰 빈틈이 발생하면 해당 파츠에 경고를 표시한다.

### 6. 사용성·모델 관리·실제 인계 검증

- 모델 관리 화면에서 역할별 준비 상태, 다운로드 크기, 버전과 로컬 연결을 제공한다. 설치 동작에서만 다운로드하며 SHA-256 검증 후 원자적으로 교체한다. 모델 파일을 드롭 이미지마다 다시 고르지 않도록 설정을 저장한다.
- Tauri 상태에 모델 세션을 캐시한다. 활성 분석 작업은 하나로 제한하고, `jobId`·이미지 revision으로 늦게 도착한 결과를 폐기한다. 단계별 진행률과 취소를 제공하고, 실행 중인 추론의 강제 중단 가능 여부는 따로 검증한다.
- 브라우저 모드에서는 네이티브 분석 미지원 상태를 명확히 보인다. 실제 모델 기능과 IPC는 `npm run desktop`으로 검증한다. 배포 빌드는 인계 확인 시 사용한다.
- 실제 Cubism Editor에서 PSD 가져오기, 레이어 이름/순서/오프셋/알파, 저장 후 재열기를 확인한다. Editor 버전과 검증 자료를 보고서에 남긴다. Editor 검증을 실행하지 못한 항목은 미검증 상태로 유지한다.

완료 조건: 이미지 입력부터 기본 분석까지 모델 경로나 기술 설정을 반복 입력하지 않는다. 수정/취소/다른 이미지 입력 후에도 오래된 결과가 현재 프로젝트를 덮어쓰지 않는다. 인계 성공 여부를 PSD 구조 검사와 실제 Editor 검증으로 나누어 표시한다.

## 평가 기준

아래 수치는 채택 판단을 위한 초기 목표이며 현재 성능 측정값이 아니다. 평가 이미지 수가 적으므로 케이스별 결과와 실패 유형을 함께 공개하고 수치만으로 일반 성능을 주장하지 않는다.

| 항목        | 측정 방법과 초기 목표                                                                                                                                                                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 얼굴 검출   | 별도 정면 원화 20장 중 18장 이상에서 정답 박스 IoU ≥ 0.5. 얼굴 없는 10장 중 오검출 1장 이하. 다중 얼굴 케이스는 대상 선택 동작으로 따로 평가                                                                                                            |
| 랜드마크    | 검출 성공 여부와 별개로 정답 박스 입력에서도 측정. 눈 중심·입 중심·턱의 오차를 얼굴 박스 대각선으로 나눈 평균 ≤ 0.05, 이미지별 평균의 p90 ≤ 0.10. 미검출은 전체 성공률에서 실패로 집계                                                                  |
| 보이는 파츠 | 가림/미해당을 주석으로 구분. 마스크가 정의된 파츠의 클래스별 IoU와 평균을 보고. 큰 파츠 평균 IoU ≥ 0.80, 작은 눈·입 평균 ≥ 0.65를 초기 채택 기준으로 사용                                                                                               |
| 보정 비용   | 자동 결과와 사용자 클릭 최대 3회 후 결과를 따로 측정. 이미지당 전체 보정 시간, 파츠당 클릭 수, 브러시 필요 여부를 기존 기하 분할과 동일 자료에서 비교                                                                                                   |
| 합성        | 보완 전 보이는 파츠를 합친 원본 대비 오차와 미할당 전경 비율을 기록. 보완 후에는 최종 레이어 합성 결과를 별도로 비교                                                                                                                                    |
| 실행 성능   | Windows CPU 기준 첫 로드/후속 분석, 이미지 인코딩/클릭 디코딩, peak RAM을 각각 p50/p95로 기록. 작업 이미지 긴 변 2,048px에서 후속 전체 분석 p95 ≤ 30초, 캐시 후 클릭 응답 p95 ≤ 1초, peak RAM ≤ 2GiB를 초기 목표로 두고 대상 CPU·스레드를 보고서에 기록 |
| 데이터 보존 | v1→v2 마이그레이션, 재분석 시 수동 수정 보존, 저장 재열기, 취소/이미지 교체 경쟁 조건을 통과                                                                                                                                                            |
| 인계        | PSD 구조 테스트와 실제 Cubism 가져오기·저장 재열기를 모두 통과                                                                                                                                                                                          |

schema v2 뼈대와 v1 마이그레이션은 3번 커밋에 포함하고, 5번에서 보완 영역까지 확장한다. 각 커밋은 기존 편집·저장·내보내기 경로가 동작하는 상태로 유지한다.

첫 구현은 **평가 가능한 얼굴 검출·랜드마크 ONNX 파이프라인**이다. 자동 파츠 분리 품질을 확인하기 전에 물리 효과나 방송 기능을 확장하지 않는다. 전신, 웹캠, 타임라인, 직접 CMO3/MOC3 생성은 이번 범위에 포함하지 않는다.
