# flat2rig 구현 작업 지시서

작성일: 2026-11-15 · 개정일: 2026-11-16 (`v0.2.0-3` 기반 반영 및 T8–T12 숨은 영역 확장·겹침·모션 검증 태스크 추가) · 2026-11-18 (T8 1차 구현 검수, T13–T16 추가, T8 이후 실행 순서 재정렬). 제품 범위의 기준은 [product-plan.md](product-plan.md)다. 아래 작업은 시간표가 아니라 의존성에 따른 실행 순서다.

## 개발자에게 전달할 지시

> 목표를 단순 정지 원화 보존에서 **원본의 시각적 정체성을 유지하면서 보이지 않는 숨은 영역까지 완성해 자연스럽게 움직이는 캐릭터 편집·재생기**로 정렬한다. 기존 Rust + Tauri v2, ort, delaunator, glam, React/Canvas·WebGL 기반과 `Part.mask` / `Part.fillMask` / `Part.texture` / `Part.compositeOrder` / `RigProfile.clippingTargets` 구조를 유지·확장한다.
> 개발 우선순위는 **`소체 피팅 → 숨은 영역 확장 → 원본과 자연스러운 합성 → 모션 시 겹침 검증`**이다. XYZ 모션 각도를 줄여 결함을 숨기지 않고, 독립 메쉬와 텍스처가 움직이는 상태에서 5대 모션·이음새 기준(기본 포즈 자연스러움, 얼굴·목 반대 이동 공백, 눈 감김 누출, 머리카락 이동 배경 노출, 경계 이중 선화/흰 테두리)을 통과시켜야 한다. PSD 인계는 고급 출력으로 유지한다.
> **(2026-11-18 보완)** 결함 0은 "원본처럼 보인다"는 뜻이 아니다. 숨은 영역 품질은 허용 모션에서 실제로 드러나는 **노출 영역**을 기준으로 측정하고, 개선 순서는 **측정(T14) → 노출 축소(T13) → 영역 유형별 합성(T9·T15) → 수동 보정(T11) → 게이트(T12)**로 진행한다. 근거는 [template-architecture-review.md](template-architecture-review.md) 2026-11-18 항목에 있다.

## 공통 작업 규칙

- `AGENTS.md`, `DESIGN.md`를 따른다. CodeGraph가 있으면 코드 위치·호출 관계를 먼저 확인한다.
- 현재 구현(`v0.2.0-3`: T0–T6 및 4단계 실루엣 적층 완료, T8 1차 구현 `79610ec`)과 신규 요구(T8 재검수, T9–T16 및 T7 잔여 검증)를 구분한다. 이미 구현된 경로를 중복 구현하거나 되돌리지 않는다.
- 각 작업은 실행 가능한 상태로 마친다. 전체를 재작성하거나 먼저 렌더러/추론 라이브러리를 교체하지 않는다.
- 수동·승인 파츠, 가변 머리카락 ID, 가시 영역(`mask`)과 숨은 영역(`fillMask`) 분리, 캐릭터 기준 L/R을 유지한다.
- ONNX 변경 시 `onnx-model-pipeline`, PSD/인계 변경 시 `cubism-psd-handoff` 스킬을 적용한다. 이번 목표 때문에 모델 재학습이나 SDK 도입을 선행 조건으로 만들지 않는다.
- 기존 작업 파일을 한꺼번에 스테이징하지 않는다. 구현 담당자는 자신이 바꾼 범위와 검증 자료를 명시한다.

## T0. 현재 기반을 확인하고 회귀 자료 고정

선행: 없음. 우선 확인: `analysis/templates.rs`, `analysis/parts.rs`, `src/io.ts`, `src/App.tsx`, 기존 파이프라인 테스트.

작업:

- 현재 수정된 역방향 smoothstep, 원화 가시 픽셀 보존, 동적 파츠·수동 수정 병합, 템플릿/머리 분리 옵션을 확인한다.
- 참고 PSD의 합성 이미지와 별도 일반형 2장·SD형 3장 이상을 고정 입력으로 준비한다. 참고 PSD 레이어는 가림 구조의 비교 자료로만 사용한다.
- 입력/기본 합성/보완 합성/눈·입 확대를 저장한다. CLI와 GUI의 래스터라이저 차이를 구분한다.
- 원화 유지 모드와 명시적인 스타일 변경 모드를 분리한다. 근거 없는 매칭 백분율을 품질 보증으로 사용하지 않는다.
- 재분석 시 수정·승인 상태의 기본/추가 파츠가 사라지거나 다른 파츠와 겹치지 않는지 확인한다. 보존 파츠끼리 이미 겹친 경우도 조용히 성공 처리하지 않는다.

완료: 원화 유지 모드에서 가시 마스크 합=원본 전경 알파, 가시 RGB 재합성 기준을 통과한다. 합성 테스트에서는 정확 일치를 검사하고, 실제 렌더 경로의 색/알파 오차는 허용값과 이유를 보고서에 기록한다. 가림 보완으로 새로 그린 영역은 별도 비교한다. 실패한 입력을 숨기지 않는다.

산출물: 재현 명령, 이미지별 분석/보정 상태, 비교 이미지, 현재 실패 목록. `docs/validation.md`의 기존 기록을 지우지 않고 새 검증을 구분해 추가한다.

## T1. 프로젝트 v3와 편집 데이터 계약

선행: T0. 주요 파일: `src/types.ts`, `src/io.ts`, `src/demo.ts`, 저장·불러오기 테스트.

작업:

- `RigProfile`, `ShapePreset`, `ExpressionPreset`, `PlaybackSettings`를 제품 계획서의 의미로 정의한다. 프리셋 ID와 표시 이름은 분리한다.
- `Project.schemaVersion`을 3으로 확장하고 v1/v2→v3 마이그레이션을 추가한다. 이전 데이터에는 원화 모양·REST·자동 움직임 기본값을 넣고 기존 파츠/보완을 보존한다.
- 모양 자산은 ZIP 내부 파일로 저장한다. 자산 참조·마스크 크기·캔버스 크기·숫자 범위·프리셋 수·압축 해제 총량을 검증한다. 누락 참조는 복구 안내 또는 명시적 오류로 처리한다.
- 기본 표정과 편집 결과를 저장한다. 일시적인 테스트 슬라이더 값·시간·물리 속도는 영구 설정과 분리한다.
- 모양/표정/리깅 조정도 기존 undo/redo 기록 대상에 포함한다. 슬라이더/핸들 드래그 한 번은 기록 한 단계로 처리한다.

완료: v1/v2 파일이 열리고 v3 저장 후 재열기에서 ID·파츠·원화·모양·표정·조정값이 유지된다. 모델 미설치 PC에서도 저장된 프로젝트를 편집·재생할 수 있다. 손상/초과 용량/알 수 없는 미래 버전 입력을 명시적으로 처리한다.

## T2. 공통 평가기와 렌더 경로

선행: T1. 주요 파일: `src/Viewport.tsx`, `src/engine.ts`, `src-tauri/src/core.rs`, `src/native.ts`. 신규 모듈 제안: `src/rig/evaluate.ts`, `src/rig/render.ts`.

작업:

- `Viewport.tsx`의 자동 포즈·깜빡임·물리를 평가기로, 캐릭터 합성을 공통 렌더 함수로 분리한다. 메쉬 오버레이·선택 UI는 편집 화면에 남긴다.
- 평가 입력은 프로젝트 프로파일·표정 선택/강도·수동 입력·시간/시간차다. 출력은 최종 파라미터·부위별 활성 모양·클리핑 정보다. 썸네일 렌더는 고정 시간과 초기 물리 상태로 결정적으로 실행한다.
- 입력을 기본값→표정→부위별 수동 조정→허용된 자동 동작→범위 제한 순으로 해결하고 물리를 적용한다. 부분 파라미터를 이전 프레임에 계속 더하지 않는다.
- 현재 자동 모션의 입 개폐는 사용자 재생의 기본 동작에서 제거한다. 테스트 기능으로 남기면 별도 스위치와 명칭을 둔다.
- 추가 부위 프로파일이 Rust/TS 변형에 영향을 주면 양쪽 계약을 함께 갱신한다. TS만 별도 수식으로 움직이게 두지 않는다.

완료: 기존 REST/대표 포즈가 리팩터링 전과 동일하고, 같은 입력을 고정 시간에 평가하면 같은 결과가 나온다. 반복 표정 전환에 드리프트가 없고 정지/재열기 후 물리 속도가 남지 않는다. 이후 PNG·재생 화면도 이 경로를 사용한다.

## T3. 눈 모양 라이브러리와 조정

선행: T0~T2. 주요 파일: `templates.rs`, `engine.ts`, `core.rs`, 신규 `src/rig/` 모듈, `Viewport.tsx`와 눈 편집 컴포넌트.

작업:

- 원래 눈/반감김/감은 눈/웃는 눈의 레시피를 일반형·SD형 기준으로 만든다. 원래 눈은 가시 원화 유지가 기준이다.
- 기존 눈 개폐·눈웃음·시선 파라미터를 재사용한다. 변형만으로 안 되는 모양은 버전이 있는 대체 파츠 세트로 생성한다.
- 눈 양 끝·위/아래 곡률·홍채 중심 등을 제한된 핸들로 조정한다. 정규화 좌표와 작업 캔버스 변환을 명시한다. 좌우 연결 편집은 반사 변환을 사용하고 L/R ID를 바꾸지 않는다.
- 흰자 클리핑, 감김에 따른 홍채/하이라이트 숨김, 원래 눈 픽셀 잔류를 처리한다. 생성 모양 적용은 현재 캐릭터의 미리보기와 원래대로 복귀를 제공한다.

완료: 좌/우 윙크, 감은 눈+자동 깜빡임, 웃는 눈+시선 극값을 정면/작은 고개 회전에서 확인한다. 눈이 두 벌 보이거나 홍채가 새거나 가림 보완 피부색이 튀지 않는다. 한쪽 조정이 다른 쪽에 의도 없이 적용되지 않는다. 생성 실패는 `수정 필요`다.

## T4. 입 모양 라이브러리와 조정

선행: T0~T2. 주요 파일: T3의 공통 모듈과 입 편집 컴포넌트. T3의 자산/핸들/클리핑 기반을 재사용한다.

작업:

- 원래 입/닫힌 입/A/I/U/E/O를 정의한다. 기존 `mouth`와 `mouthForm` 값을 달리한 것만으로 완료하지 않는다.
- 모양별 폭·개구 높이·둥글기·입꼬리·윗/아랫입술 곡선·입안 노출을 정의한다. 필요한 형상 축은 부위 프로파일에 명시하고 변형 또는 대체 파츠 세트를 선택한다.
- 입꼬리/위·아래 경계 핸들, 위치·크기, 벌어짐 강도를 조정한다. 입안은 피부 위로 새지 않고 닫힐 때 사라지게 한다. 혀/치아가 없으면 생성한 것처럼 표시하지 않는다.
- 기본 모양에서 원래 입을 유지하고 다른 모양으로 전환할 때 원래 입 선이 얼굴에 남지 않게 한다.

완료: 동일 크기의 7개 썸네일에서 모양 차이를 확인할 수 있고 U/O, I/E가 단순 크기 차이로만 처리되지 않는다. 입 개폐 0/0.5/1과 미소/화남 표정의 조합을 확인한다. 음성·음소 인식 기능으로 표시하지 않는다.

## T5. 표정과 리깅 세부 조정

선행: T3, T4. 주요 파일: `src/App.tsx`, `src/types.ts`, 신규 표정/조정 컴포넌트, 공통 평가기.

작업:

- 기본/미소/기쁨/화남/슬픔/놀람/캐릭터 좌·우 윙크를 제공한다. 썸네일은 현재 캐릭터로 렌더한다.
- 눈 모양·입 모양·눈썹·파라미터를 조합해 사용자 표정을 저장/복제/이름 변경/삭제한다. 원래 기본 상태는 삭제할 수 없게 한다.
- 표정 강도와 전환 시간, 고개·시선·머리 물리 강도와 안전 범위를 조정한다. 기본 고개 범위는 작게 시작하며 공식 파라미터 정의 범위를 임의로 줄이지 않는다. 프로파일의 안전 범위로 제한한다.
- 닫힌 눈/윙크의 소유권이 자동 깜빡임보다 우선하도록 한다. 모양 전환과 연속 파라미터 보간을 구분하고 선화 이중상·입안 깜빡임을 검사한다.
- 누락된 눈/입 세부 파츠에서는 해당 프리셋을 정상 완료처럼 적용하지 않는다. 보정 화면으로 연결한다.

완료: 표정을 빠르게 교체해도 이전 표정 값이 잔류하지 않고 기본 복귀가 정확하다. 강도 0/0.5/1, 단독/자동 모션 조합, undo/redo, 저장/재열기를 확인한다. 슬라이더만 움직이고 저장되지 않는 구현은 미완료다.

## T6. 기본 화면 전환과 앱 내 완결

선행: T2~T5. 주요 파일: `src/App.tsx`, UI 컴포넌트, `design.css`, `style.css`, `src/images.ts`, `src/io.ts`.

작업:

- 기본 흐름을 `준비 → 표정 → 조정 → 재생`으로 바꾸고 파츠/메쉬/모델 관리와 Cubism 인계는 고급 영역에 둔다. 기존 저장·단축키·오류·취소·드롭 동작을 유지한다.
- 전용 재생 화면에 수동 표정 버튼, 앱 포커스 단축키, 깜빡임/호흡/유휴 움직임 토글, 일시정지·기본 복귀를 제공한다.
- 현재 프레임을 투명 PNG로 출력한다. 체커보드·핸들·메쉬·선택 표시를 포함하지 않는다. 편집/재생과 동일한 평가 시점과 렌더 경로를 사용한다.
- 새 대체 모양을 기존 PSD 인계에서 어떻게 다룰지 표시한다. 이번 기본 인계는 원화 기반 기본 파츠이며 앱 표정이 Cubism으로 자동 이전되지 않는다고 안내한다. 활성 모양 출력 같은 추가 옵션은 실제 저장·재읽기·모드 계약을 구현한 뒤 노출한다.
- Windows 네이티브에서 모델 없는 저장 파일 재생과 오류/취소 복구를 확인한다. 설치 없는 배포를 표방하려면 별도 PC의 WebView2·ONNX 런타임 의존성과 자산 경로를 검증한다.

## T8. 부위별 모션 비례 겹침 여유분(`fillMask`) 확장 (`1차 구현 · 재검수 항목 있음`)

선행: `v0.2.0-3` (T0–T6). 주요 파일: `src-tauri/src/analysis/templates.rs`, `src-tauri/src/core.rs`, `src/engine.ts`.

## T13. 이음새 계약(`SeamGraph`) · 노출 맵(`ExposureMap`) · 이음새 결합 변형

선행: T8. 주요 파일: `src-tauri/src/core.rs`, `src/engine.ts`, `src-tauri/src/analysis/templates.rs`, `src/types.ts`, `src/rig/evaluate.ts`. 신규 모듈 제안: `src-tauri/src/rig/seams.rs`(또는 `core.rs` 내 분리 모듈).

목적: 여유분·숨은 영역 생성·노출 평가·T12 검사가 공유하는 **단일 이음새 기준**을 만든다. 손으로 옮긴 변형 상수를 없앤다.

작업:

- **이음새 계약**: 4단계 적층 결과에서 상하 관계가 있는 파츠 쌍을 `SeamContract { upper, lower, boundary(가시 경계 폴리라인), coupling }`로 추출한다. 파츠는 ID가 아니라 역할(`role`)로 식별하며 가변 머리카락·액세서리를 포함한다. 프로젝트에 저장할 필요가 없는 파생 데이터로 두고, 사용자가 수정·승인한 마스크가 바뀌면 다시 계산한다.
- **포즈 포락선**: `PARAM_DEFS` 정의 범위 전체(축소 금지)의 각 축 극값, 머리/몸 반대 방향 조합, 머리카락 흔들림 위상(±1과 위상차)으로 구성한 결정적 샘플 포즈 집합을 정의한다. 샘플 집합은 Rust/TS가 공유하는 데이터(상수 표)로 둔다.
- **수치 여유분**: 각 이음새 경계점을 `deform(upper)`와 `deform(lower)`로 변형해 상대 변위의 최댓값을 구하고, 안전 계수를 더해 이음새별 필요 언더랩으로 쓴다. `PartOverlapMargins`는 랜드마크만 있고 이음새가 없을 때의 폴백으로 격하한다.
- **노출 맵**: 포락선 샘플 포즈마다 렌더 순서·클리핑을 적용해 각 파츠의 숨은 픽셀(`fillMask`) 중 최상위로 드러나는 픽셀을 누적한다. 파츠별 `노출 빈도`(0..1)와 `최대 노출 깊이`(px, 가시 경계로부터 거리)를 산출한다. 노출되지 않는 숨은 영역은 품질 대상에서 제외하되 PSD 인계용 연속성은 유지한다.
- **결합 변형**: 이음새 양쪽의 변형장이 이음새 근처에서 연속되도록 결합 가중치를 정의한다(머리카락 뿌리↔두피, 목 상단↔머리 회전 감쇠 추종, 옷깃↔몸통). **최대 각도와 파라미터 범위는 바꾸지 않는다.** `core.rs`와 `engine.ts`를 같은 수식으로 갱신하고 동등성 테스트를 확장한다.
- 노출 맵을 CLI `stats.json`과 고급 화면 오버레이(노출 빈도 히트맵)로 출력한다.

완료: (1) 여유분 산출에 `deform` 계수의 수작업 복제가 없고, `deform` 계수를 바꾸면 테스트가 여유분 재계산을 확인한다. (2) 모든 이음새 경계점 × 포락선 포즈에서 하위 파츠의 변형된 유효 마스크가 상위 파츠의 변형된 가시 경계 밴드를 덮는다(커버리지 위반 0 또는 위반 위치 보고). (3) 결합 변형 전후 노출 면적·최대 노출 깊이를 원화 3종에서 기록한다. (4) Rust/TS 동일 입력 동일 결과.

## T14. 숨은 영역 원본감 평가 하네스

선행: T13(노출 맵). 주요 파일: `src-tauri/src/bin/flat2rig-cli.rs`, `tools/evaluation/`, `docs/validation.md`. Python은 평가·리포트에만 사용한다(AGENTS.md 4절).

목적: "원본처럼 보이는가"를 측정 가능한 수치로 바꾼다. **합성기 개선(T9·T15·T16) 전에 현재 조화 보간 합성기의 기준선을 먼저 기록한다.**

작업:

- **정답 비교 세트**: 참고 PSD(`Himikan`)의 레이어를 합성한 평면 이미지를 입력으로 실행하고, 각 파츠의 생성 숨은 텍스처를 실제 PSD 레이어의 가려진 픽셀과 비교한다. 레이어↔파츠 대응표는 수동으로 고정하고 버전을 붙인다. 참고 PSD는 평가에만 쓰며 배포 자산으로 쓰지 않는다. 추가 레이어 PSD를 확보하면 같은 절차로 넣는다(권리 확인).
- **자기 지도 홀드아웃**: 정답 레이어가 없는 원화에서는 파츠의 보이는 영역 중 이음새에 인접한 밴드(폭 = 해당 이음새의 최대 노출 깊이)를 가리고, 숨은 영역과 같은 경로로 합성한 뒤 원래 픽셀과 비교한다. 홀드아웃은 평가 전용이며 결과 프로젝트에 반영하지 않는다.
- **지표(노출 밴드 안에서만 계산)**: ΔE2000 평균·p95, 파츠 팔레트 군집 일치율, 이음새를 가로지르는 그래디언트 불연속, 경계를 지나는 선화 획의 끊김 수, 질감 통계 차이(국소 분산). 노출 빈도로 가중한 값도 함께 기록한다.
- 결과를 CLI `stats.json`의 별도 키와 `docs/validation.md`의 별도 절에 기록하고, 비교 이미지(정답 / 합성 / 차이)를 `artifacts/`에 저장한다.

완료: 원화 3종 + 참고 PSD에서 현 합성기의 기준선 수치와 비교 이미지가 남는다. 임계값은 기준선과 육안 판정을 대조해 정하고 근거를 기록한다. 근거 없는 백분율이나 단일 종합 점수를 품질 보증으로 표시하지 않는다.

## T15. 선화·구조 연장 (숨은 윤곽선 포함)

선행: T9, T14. 주요 파일: `src-tauri/src/analysis/templates.rs`(또는 신규 `analysis/lineart.rs`), `src-tauri/src/core.rs`.

목적: 조화 보간 색상 필드가 만들 수 없는 선 구조(얼굴 윤곽선, 목 옆선, 머리카락 결, 옷깃 테두리)를 노출 밴드 안에서 원화 규칙대로 잇는다.

작업:

- 파츠 텍스처를 **선화 레이어**(어둡고 가는 획)와 **채색 레이어**로 분리한다. 채색 레이어는 T9 필드로, 선화 레이어는 별도로 합성한 뒤 다시 합친다.
- 가시 경계에서 끊기는 선화 획을 찾아 접선·곡률을 피팅하고, 최대 노출 깊이까지 연장한다. 획 굵기·색·끝 처리(가늘어짐)는 같은 파츠의 원화 획 통계를 따른다. 연장이 다른 획과 교차하거나 확신이 낮으면 연장하지 않고 `semantic`으로 표시한다.
- **숨은 윤곽선**: `fillMask`가 실루엣을 확장한 구간(예: 옆머리 아래 얼굴 가장자리, 옷깃 아래 목 옆선)에는 원화 윤곽선과 같은 굵기·색의 윤곽선을 템플릿 SDF 경계를 따라 생성한다. 보이는 윤곽선과 이어지는 지점에서 굵기·색이 연속되어야 한다.
- 머리카락 결처럼 반복적인 선은 같은 파츠의 획 방향장을 따라 연장하되, 노출 깊이를 넘는 영역에 새 획을 만들어 넣지 않는다.

완료: T14 지표에서 노출 밴드의 선화 끊김 수가 기준선보다 줄고, 옆머리 흔들림·고개 회전 포즈에서 얼굴·목 가장자리 윤곽선이 연속된다. 이중 선화(5대 기준 ⑤)가 새로 생기지 않는다.

## T16. (조건부) 질감 예시 합성 · 생성형 인페인팅 연구

선행: T14 기준선과 T9·T15 결과. **착수 조건**: T14 수치에서 `texture`/`semantic` 노출 밴드가 T9·T15 이후에도 육안 판정상 원화와 구분될 때만 착수한다. 이 작업은 다른 작업의 선행 조건이 아니다.

- **질감 예시 합성(비생성형 우선)**: 같은 파츠 내측의 예시 패치를 사용하는 PatchMatch 계열 합성을 결정적 시드로 수행한다. 의상 무늬·머리카락 결 질감에 적용하고, 결과가 다른 파츠 색을 끌어오지 않도록 출처 영역을 해당 파츠 `mask` 내측으로 제한한다.
- **생성형 인페인팅(연구 트랙)**: 로컬 ONNX 인페인팅 모델을 검토한다. 채택하려면 `models/manifest.json` 등록, `onnx-model-pipeline` 절차에 따른 Python↔Rust `ort` 오차 검증, 라이선스·배포 크기·CPU 지연 측정이 필요하다. 결과는 `fillKind` 출처를 `generated`로 구분해 표시하며, 원화 `mask` 영역에는 절대 적용하지 않는다.

완료: 채택 여부와 근거(T14 수치 비교, 비용)를 문서에 남긴다. 채택하지 않으면 해당 영역은 `semantic`/수동 영역으로 유지한다.
