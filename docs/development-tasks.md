# flat2rig 구현 작업 지시서

작성일: 2026-11-15. 제품 범위의 기준은 [product-plan.md](product-plan.md)다. 아래 작업은 시간표가 아니라 의존성에 따른 실행 순서다.

## 개발자에게 전달할 지시

> 목표를 Cubism 후처리 자료 생성기에서 앱 안에서 표정과 기본 움직임을 완성하는 캐릭터 편집·재생기로 전환한다. 기존 Rust + Tauri v2, ort, delaunator, glam, React/Canvas 기반을 유지한다. 일반형/SD형 피팅과 원화 보존을 바탕으로 눈·입 모양, 표정 저장, 제한된 핸들 조정, 공통 재생기, 프로젝트 저장·재열기를 구현한다. PSD 인계는 고급 출력으로 유지한다. 문서만 작성하거나 UI 카드만 추가한 상태로 완료하지 말고, 실제 이미지에서 모양 차이·클리핑·조합·재열기를 증명한다. 현재 미커밋 변경과 이전 수정 사항을 확인하고 중복 구현하거나 되돌리지 않는다.

## 공통 작업 규칙

- `AGENTS.md`, `DESIGN.md`를 따른다. CodeGraph가 있으면 코드 위치·호출 관계를 먼저 확인한다.
- 현재 구현과 신규 요구를 구분한다. 이전 검토 문서의 오류가 이미 수정됐으면 재구현하지 말고 회귀 검증한다.
- 각 작업은 실행 가능한 상태로 마친다. 전체를 재작성하거나 먼저 렌더러/추론 라이브러리를 교체하지 않는다.
- 수동·승인 파츠, 가변 머리카락 ID, 원화와 가림 보완 분리, 캐릭터 기준 L/R을 유지한다.
- ONNX 변경 시 `onnx-model-pipeline`, PSD/인계 변경 시 `cubism-psd-handoff` 스킬을 적용한다. 이번 목표 때문에 모델 재학습이나 SDK 도입을 선행 조건으로 만들지 않는다.
- 기존 작업 파일을 한꺼번에 스테이징하지 않는다. 구현 담당자는 자신이 바꾼 범위와 검증 자료를 명시한다.

## T0. 현재 기반을 확인하고 회귀 자료 고정

선행: 없음. 우선 확인: `analysis/templates.rs`, `analysis/parts.rs`, `src/io.ts`, `src/App.tsx`, 기존 파이프라인 테스트.

작업:

- 현재 수정된 역방향 smoothstep, 원화 가시 픽셀 보존, 동적 파츠·수동 수정 병합, 템플릿/머리 분리 옵션을 확인한다.
- 참고 PSD의 합성 이미지와 별도 일반형 2장·SD형 3장 이상을 고정 입력으로 준비한다. 참고 PSD 레이어는 가림 구조의 비교 자료로만 사용한다.
- 입력/기본 합성/보완 합성/눈·입 확대를 저장한다. CLI와 GUI의 래스터라이저 차이를 구분한다.
- 원화 유지 모드와 명시적인 스타일 변경 모드를 분리한다. 근거 없는 매칭 백분율을 품질 보증으로 사용하지 않는다.
- 재분석 시 수정·승인 상태의 기본/추가 파츠가 사라지거나 다른 파츠와 겹치지 않는지 확인한다. 보존 파츠끼리 이미 겹친 경우도 조용히 성공 처리하지 않는다.

완료: 원화 유지 모드에서 가시 마스크 합=원본 전경 알파, 가시 RGB 재합성 기준을 통과한다. 합성 테스트에서는 정확 일치를 검사하고, 실제 렌더 경로의 색/알파 오차는 허용값과 이유를 보고서에 기록한다. 가림 보완으로 새로 그린 영역은 별도 비교한다. 실패한 입력을 숨기지 않는다.

산출물: 재현 명령, 이미지별 분석/보정 상태, 비교 이미지, 현재 실패 목록. `docs/validation.md`의 기존 기록을 지우지 않고 새 검증을 구분해 추가한다.

## T1. 프로젝트 v3와 편집 데이터 계약

선행: T0. 주요 파일: `src/types.ts`, `src/io.ts`, `src/demo.ts`, 저장·불러오기 테스트.

작업:

- `RigProfile`, `ShapePreset`, `ExpressionPreset`, `PlaybackSettings`를 제품 계획서의 의미로 정의한다. 프리셋 ID와 표시 이름은 분리한다.
- `Project.schemaVersion`을 3으로 확장하고 v1/v2→v3 마이그레이션을 추가한다. 이전 데이터에는 원화 모양·REST·자동 움직임 기본값을 넣고 기존 파츠/보완을 보존한다.
- 모양 자산은 ZIP 내부 파일로 저장한다. 자산 참조·마스크 크기·캔버스 크기·숫자 범위·프리셋 수·압축 해제 총량을 검증한다. 누락 참조는 복구 안내 또는 명시적 오류로 처리한다.
- 기본 표정과 편집 결과를 저장한다. 일시적인 테스트 슬라이더 값·시간·물리 속도는 영구 설정과 분리한다.
- 모양/표정/리깅 조정도 기존 undo/redo 기록 대상에 포함한다. 슬라이더/핸들 드래그 한 번은 기록 한 단계로 처리한다.

완료: v1/v2 파일이 열리고 v3 저장 후 재열기에서 ID·파츠·원화·모양·표정·조정값이 유지된다. 모델 미설치 PC에서도 저장된 프로젝트를 편집·재생할 수 있다. 손상/초과 용량/알 수 없는 미래 버전 입력을 명시적으로 처리한다.

## T2. 공통 평가기와 렌더 경로

선행: T1. 주요 파일: `src/Viewport.tsx`, `src/engine.ts`, `src-tauri/src/core.rs`, `src/native.ts`. 신규 모듈 제안: `src/rig/evaluate.ts`, `src/rig/render.ts`.

작업:

- `Viewport.tsx`의 자동 포즈·깜빡임·물리를 평가기로, 캐릭터 합성을 공통 렌더 함수로 분리한다. 메쉬 오버레이·선택 UI는 편집 화면에 남긴다.
- 평가 입력은 프로젝트 프로파일·표정 선택/강도·수동 입력·시간/시간차다. 출력은 최종 파라미터·부위별 활성 모양·클리핑 정보다. 썸네일 렌더는 고정 시간과 초기 물리 상태로 결정적으로 실행한다.
- 입력을 기본값→표정→부위별 수동 조정→허용된 자동 동작→범위 제한 순으로 해결하고 물리를 적용한다. 부분 파라미터를 이전 프레임에 계속 더하지 않는다.
- 현재 자동 모션의 입 개폐는 사용자 재생의 기본 동작에서 제거한다. 테스트 기능으로 남기면 별도 스위치와 명칭을 둔다.
- 추가 부위 프로파일이 Rust/TS 변형에 영향을 주면 양쪽 계약을 함께 갱신한다. TS만 별도 수식으로 움직이게 두지 않는다.

완료: 기존 REST/대표 포즈가 리팩터링 전과 동일하고, 같은 입력을 고정 시간에 평가하면 같은 결과가 나온다. 반복 표정 전환에 드리프트가 없고 정지/재열기 후 물리 속도가 남지 않는다. 이후 PNG·재생 화면도 이 경로를 사용한다.

## T3. 눈 모양 라이브러리와 조정

선행: T0~T2. 주요 파일: `templates.rs`, `engine.ts`, `core.rs`, 신규 `src/rig/` 모듈, `Viewport.tsx`와 눈 편집 컴포넌트.

작업:

- 원래 눈/반감김/감은 눈/웃는 눈의 레시피를 일반형·SD형 기준으로 만든다. 원래 눈은 가시 원화 유지가 기준이다.
- 기존 눈 개폐·눈웃음·시선 파라미터를 재사용한다. 변형만으로 안 되는 모양은 버전이 있는 대체 파츠 세트로 생성한다.
- 눈 양 끝·위/아래 곡률·홍채 중심 등을 제한된 핸들로 조정한다. 정규화 좌표와 작업 캔버스 변환을 명시한다. 좌우 연결 편집은 반사 변환을 사용하고 L/R ID를 바꾸지 않는다.
- 흰자 클리핑, 감김에 따른 홍채/하이라이트 숨김, 원래 눈 픽셀 잔류를 처리한다. 생성 모양 적용은 현재 캐릭터의 미리보기와 원래대로 복귀를 제공한다.

완료: 좌/우 윙크, 감은 눈+자동 깜빡임, 웃는 눈+시선 극값을 정면/작은 고개 회전에서 확인한다. 눈이 두 벌 보이거나 홍채가 새거나 가림 보완 피부색이 튀지 않는다. 한쪽 조정이 다른 쪽에 의도 없이 적용되지 않는다. 생성 실패는 `수정 필요`다.

## T4. 입 모양 라이브러리와 조정

선행: T0~T2. 주요 파일: T3의 공통 모듈과 입 편집 컴포넌트. T3의 자산/핸들/클리핑 기반을 재사용한다.

작업:

- 원래 입/닫힌 입/A/I/U/E/O를 정의한다. 기존 `mouth`와 `mouthForm` 값을 달리한 것만으로 완료하지 않는다.
- 모양별 폭·개구 높이·둥글기·입꼬리·윗/아랫입술 곡선·입안 노출을 정의한다. 필요한 형상 축은 부위 프로파일에 명시하고 변형 또는 대체 파츠 세트를 선택한다.
- 입꼬리/위·아래 경계 핸들, 위치·크기, 벌어짐 강도를 조정한다. 입안은 피부 위로 새지 않고 닫힐 때 사라지게 한다. 혀/치아가 없으면 생성한 것처럼 표시하지 않는다.
- 기본 모양에서 원래 입을 유지하고 다른 모양으로 전환할 때 원래 입 선이 얼굴에 남지 않게 한다.

완료: 동일 크기의 7개 썸네일에서 모양 차이를 확인할 수 있고 U/O, I/E가 단순 크기 차이로만 처리되지 않는다. 입 개폐 0/0.5/1과 미소/화남 표정의 조합을 확인한다. 음성·음소 인식 기능으로 표시하지 않는다.

## T5. 표정과 리깅 세부 조정

선행: T3, T4. 주요 파일: `src/App.tsx`, `src/types.ts`, 신규 표정/조정 컴포넌트, 공통 평가기.

작업:

- 기본/미소/기쁨/화남/슬픔/놀람/캐릭터 좌·우 윙크를 제공한다. 썸네일은 현재 캐릭터로 렌더한다.
- 눈 모양·입 모양·눈썹·파라미터를 조합해 사용자 표정을 저장/복제/이름 변경/삭제한다. 원래 기본 상태는 삭제할 수 없게 한다.
- 표정 강도와 전환 시간, 고개·시선·머리 물리 강도와 안전 범위를 조정한다. 기본 고개 범위는 작게 시작하며 공식 파라미터 정의 범위를 임의로 줄이지 않는다. 프로파일의 안전 범위로 제한한다.
- 닫힌 눈/윙크의 소유권이 자동 깜빡임보다 우선하도록 한다. 모양 전환과 연속 파라미터 보간을 구분하고 선화 이중상·입안 깜빡임을 검사한다.
- 누락된 눈/입 세부 파츠에서는 해당 프리셋을 정상 완료처럼 적용하지 않는다. 보정 화면으로 연결한다.

완료: 표정을 빠르게 교체해도 이전 표정 값이 잔류하지 않고 기본 복귀가 정확하다. 강도 0/0.5/1, 단독/자동 모션 조합, undo/redo, 저장/재열기를 확인한다. 슬라이더만 움직이고 저장되지 않는 구현은 미완료다.

## T6. 기본 화면 전환과 앱 내 완결

선행: T2~T5. 주요 파일: `src/App.tsx`, UI 컴포넌트, `design.css`, `style.css`, `src/images.ts`, `src/io.ts`.

작업:

- 기본 흐름을 `준비 → 표정 → 조정 → 재생`으로 바꾸고 파츠/메쉬/모델 관리와 Cubism 인계는 고급 영역에 둔다. 기존 저장·단축키·오류·취소·드롭 동작을 유지한다.
- 전용 재생 화면에 수동 표정 버튼, 앱 포커스 단축키, 깜빡임/호흡/유휴 움직임 토글, 일시정지·기본 복귀를 제공한다.
- 현재 프레임을 투명 PNG로 출력한다. 체커보드·핸들·메쉬·선택 표시를 포함하지 않는다. 편집/재생과 동일한 평가 시점과 렌더 경로를 사용한다.
- 새 대체 모양을 기존 PSD 인계에서 어떻게 다룰지 표시한다. 이번 기본 인계는 원화 기반 기본 파츠이며 앱 표정이 Cubism으로 자동 이전되지 않는다고 안내한다. 활성 모양 출력 같은 추가 옵션은 실제 저장·재읽기·모드 계약을 구현한 뒤 노출한다.
- Windows 네이티브에서 모델 없는 저장 파일 재생과 오류/취소 복구를 확인한다. 설치 없는 배포를 표방하려면 별도 PC의 WebView2·ONNX 런타임 의존성과 자산 경로를 검증한다.

완료: Cubism 없이 이미지 입력·보정·모양 선택·표정 저장·재열기·재생·PNG 출력까지 완료한다. 브라우저 대체 분석 결과만으로 네이티브 분석을 검증했다고 보고하지 않는다.

## T7. 회귀 검사와 사용자 확인

선행: T0~T6.

- `npm test`, `npm run build`, `cargo test --manifest-path src-tauri/Cargo.toml --lib`를 실행한다. 네이티브 기능 변경 시 `npm run test:native`의 범위와 실제 통과 항목을 확인한다. 모델 검사의 조기 반환은 추론 검증 통과로 세지 않는다.
- 프리셋 데이터 검증·v1/v2 마이그레이션·v3 왕복·참조 누락·수동 수정 보존·결정적 포즈 평가·Rust/TS 동등성·부위별 입력 충돌을 검증한다.
- 실제 원화 6장 이상에서 기본/각 눈·입/표정/작은 고개 조합을 같은 크기와 시점으로 기록한다. 정지 기본 상태 검사와 움직임 검사는 별개다.
- Windows에서 장시간 반복 재생 후 메모리 증가·리소스 누수·물리 시간차 급증을 확인한다. 성능 목표는 작업 캔버스 긴 변 1,024px, 캐릭터 1개, 60초 재생에서 프레임 시간 p95≤33ms다. 대상 CPU/GPU·파츠 수·해상도를 기록한다. 2,048px는 별도 측정하고 실패 시 화면 미리보기 해상도를 낮추는 선택을 제공한다.
- 신규 사용자 3명의 15분 내 완료 목표를 측정한다. 자동 결과만의 성공과 보정 후 성공, 막힌 단계·소요 시간을 분리한다.

완료: 검사 결과, 비교 이미지, 수동 확인 범위, 남은 제한을 함께 제출한다. 실제 실행하지 못한 항목은 `미검증`으로 남긴다. 새 제품 MVP의 통과 조건에 실제 Cubism 가져오기를 포함하지 않지만 기존 PSD 지원을 검증 없이 확대하지 않는다.

## 이번 지시의 종료 기준

개발자는 다음을 보고한다: 구현한 작업 ID, 변경 파일, 실행/확인 방법, 테스트 결과, 원화 비교 자료, 수동·승인 파츠 보존 결과, 저장/재열기 결과, 남은 제한. 제품 화면에 프리셋 카드가 생긴 것만으로 완료 보고하지 않는다.

기준 점검: 문서 작성 중 기존 `npm test` 27개, `cargo test --manifest-path src-tauri/Cargo.toml --lib` 26개, `npm run build` 통과. 모델·자료가 없으면 조기 반환하는 검사가 있으므로 전체 추론 정합성 통과를 뜻하지 않는다. 이 기록은 신규 기능 통과 보고가 아니다.
