# flat2rig 제품 전환 계획

작성일: 2026-11-15. 현재 작업 디렉터리의 소스 기준이며 미커밋 변경을 포함한다.

이 문서는 제품 목표와 MVP 범위의 기준이다. 기존 `mvp-spec.md`와 `implementation-plan.md`의 Cubism 인계 중심 목표를 대체한다. 구현 순서와 개발자에게 전달할 지시는 [development-tasks.md](development-tasks.md)를 따른다.

## 1. 바뀐 목표

Cubism 작업이 부담스러운 사용자가 일러스트 한 장에서 시작해, 앱 안에서 눈·입 모양과 표정을 선택하고 움직임을 조정한 캐릭터를 저장·재생하게 한다. 파츠와 메쉬를 직접 제작하는 과정 대신 미리 준비된 동작을 자신의 그림에 맞추는 과정이 기본 사용법이다.

주요 완료 지점은 **앱에서 캐릭터를 완성하고 다시 열어 재생하는 것**이다. PSD와 Cubism 인계 자료는 더 정교하게 작업하려는 사용자를 위한 선택 출력으로 유지한다. Cubism을 설치하거나 조작해야 기본 사용을 완료할 수 있는 흐름은 제거한다.

사용자가 말한 “Cubism 미니 포터블”은 기능 범위를 설명하는 내부 비유로 해석한다. 제품명은 flat2rig를 유지하며, 독립적인 편집·재생 기능을 개발한다. 설치 없는 Windows 배포는 별도 배포 검증 항목이다.

## 2. 현재 구현에서 가져갈 것

| 영역 | 현재 소스에서 확인한 내용 | 새 제품에서의 역할 |
| --- | --- | --- |
| 실행 기반 | Rust + Tauri v2 + React/TypeScript, Canvas 2D | 기존 구조 유지. 렌더러 교체부터 시작하지 않는다 |
| 분석 | `analysis/`의 ONNX 얼굴·랜드마크·배경·파츠 후보 처리 | 초기 배치 보조. 인식 실패 시 얼굴 영역과 기준점을 직접 지정 |
| 실루엣 | `templates.rs`, `TemplateStyleSelection`의 일반형/SD형 및 부위별 스타일 | 원화에 맞는 형태·가림 보완 초깃값. 표정 선택과 분리 |
| 편집 | 마스크·기준점·PNG 교체, 동적 레이어, 실행 취소/다시 실행 | 고급 보정 경로로 유지 |
| 변형 | `Parameters`/`REST`, `core.rs`, `engine.ts` | 고개·눈·시선·눈썹·입·몸·머리카락 움직임 재사용 |
| 미리보기 | `Viewport.tsx`의 텍스처 변형·눈 클리핑·자동 모션 | 공통 재생기로 추출하여 편집과 재생 화면에서 공유 |
| 저장 | `.flat2rig` ZIP, schema v2, 마스크·텍스처 보관 | 모양·표정·조정값을 포함하는 편집 가능한 프로젝트로 확장 |
| 출력 | `io.ts`의 PSD·PNG·자체 리깅 초안 | 고급 내보내기로 이동. 자체 포맷을 Cubism 공식 포맷으로 표시하지 않음 |

현재 파라미터에는 눈 개폐·눈웃음·시선·눈썹 위치/형태·입 개폐/형태·몸 회전·호흡·앞/옆/뒤 머리 움직임이 들어 있다. 따라서 처음부터 리깅 엔진 전체를 새로 만들 필요는 없다.

반면 **사용자가 저장하는 표정 프리셋, 시간에 따라 바뀌는 눈·입 모양의 독립 정의, 부위별 조정값의 저장, 입력 간 충돌을 해결하는 공통 재생기**는 이번 전환의 신규 작업이다. 현재 스타일 카탈로그의 눈·입 선택은 파츠 생성 설정이며, 재생 중 전환 가능한 모양 라이브러리와 동일하지 않다. 현재 슬라이더 값도 `Project` 밖의 UI 상태이므로 저장 계약을 추가해야 한다.

이전 [실루엣 점검](template-architecture-review.md) 이후 현재 소스에는 역방향 `smoothstep` 수정, 수정·승인 파츠 병합, 템플릿 옵션 분리, 원화 보존 회귀 검사가 추가되어 있다. 과거 발견 사항을 모두 미수정 작업으로 복사하지 않는다. 실제 일반형/SD형 원화의 기본 상태와 동작 품질은 별도로 다시 확인해야 한다.

## 3. 대상과 입력 범위

- 대상: 파츠 분리와 키폼 제작을 처음부터 하기 어려운 일러스트 작가·개인 캐릭터 사용자.
- 우선 입력: 한 명의 정면 또는 정면에 가까운 일반형/SD형 흉상 PNG/JPEG. 작업 해상도 긴 변 최대 2,048px를 유지한다.
- 자동 결과는 수정 가능한 초안이다. 실패하면 눈·입·턱 위치와 얼굴 영역을 직접 맞춘 뒤 진행할 수 있어야 한다.
- 원화에 없는 닫힌 눈·입안·다른 입모양은 추정 결과로 표시하고, 적용 전에 현재 캐릭터로 미리 보여준다.
- 초기에는 큰 고개 회전보다 정면의 표정·눈·입과 작은 움직임을 우선한다. 전신·측면·손/의상 관절은 별도 범위다.

## 4. 기본 사용 흐름과 화면

1. **준비**: 이미지 드래그 앤 드롭 → 자동 분석 → 일반형/SD형 확인 → 얼굴·눈·입 위치 보정. 원본/기본 합성 비교를 제공한다.
2. **표정**: 원화로 만든 썸네일에서 눈 모양·입 모양·표정을 고른다. 기본 표정으로 즉시 복귀할 수 있다.
3. **조정**: 선택한 눈·입의 위치·크기·입꼬리·눈꺼풀 곡률과 동작 강도를 조정한다. 파츠·메쉬·모델 설정은 고급 패널로 이동한다.
4. **재생**: 수동 표정 전환과 자동 눈 깜빡임·호흡·작은 고개/머리 움직임을 확인한다. 자동 움직임은 부위별로 끌 수 있다.
5. **저장/출력**: `.flat2rig`로 저장하고 재열기, 현재 프레임 투명 PNG 출력. 선택적으로 PSD/기존 인계 패키지를 내보낸다.

3단 작업 공간과 `DESIGN.md`의 밝은 아크릴·코발트·그라파이트 색을 유지한다. 좌측은 현재 단계에 따라 파츠 또는 모양/표정 목록, 중앙은 캐릭터, 우측은 선택한 항목의 조정값을 표시한다. 기본 화면에 전체 Live2D 파라미터 목록을 펼치지 않는다. 사용자에게 보이는 용어는 `눈 모양`, `입 모양`, `표정`, `움직임`, `원래대로`처럼 동작 중심으로 쓴다.

## 5. 이번 MVP의 기능 범위

| 기능 | 제공할 내용 | 완료 기준 |
| --- | --- | --- |
| 기본 상태 | 원화 유지, 원본/결과 전환 | 스타일 변경을 선택하지 않은 상태의 가시 RGB·알파 보존 검사와 실제 원화 비교 통과 |
| 눈 모양 | 원래 눈, 반쯤 감김, 감은 눈, 웃는 눈 | 좌우 독립 적용, 양쪽 연결 편집, 깜빡임/시선/눈웃음 조합에서 홍채가 밖으로 새지 않음 |
| 입 모양 | 원래 입, 닫힌 입, A/I/U/E/O | 벌어짐 외에 폭·둥글기·입꼬리·입안 노출이 구분됨. 정면 모양 프리셋이며 음성 인식은 아님 |
| 표정 | 기본, 미소, 기쁨, 화남, 슬픔, 놀람, 좌/우 윙크 | 조합을 저장·복제·이름 변경·초기화. 윙크의 L/R은 캐릭터 기준이고 UI에 위치를 함께 표시 |
| 세부 조정 | 눈/입 기준점과 제한된 곡선 핸들, 위치·크기·곡률, 표정 강도 | 수동 버텍스·가중치 작업 없이 조정, 원화 기준 복귀, 실행 취소/다시 실행 |
| 움직임 | 작은 고개 이동/기울임, 시선, 깜빡임, 호흡, 머리 흔들림 | 안전 범위·강도 저장, 표정과 조합, 일시정지/기본 상태 복귀 |
| 로컬 재생 | 앱 내 전용 재생 화면, 클릭/앱 포커스 단축키 표정 전환 | 편집 화면과 동일한 프레임 결과, 저장된 프로젝트를 모델 추론 없이 재생 |
| 저장/출력 | schema v3, v1/v2 읽기, 현재 프레임 PNG, 기존 고급 출력 | 재열기 후 모양·표정·조정값 유지, 현재 프레임 PNG와 재생 화면 일치 |

기본 프리셋 개수만 채워 완료 처리하지 않는다. 예를 들어 U와 O가 동일한 확대 이미지라면 미완료다. 원화 특성상 생성에 실패한 모양은 `수정 필요`로 표시하고 PNG 교체/제한된 핸들 조정으로 해결하게 한다.

## 6. 눈·입 생성과 전환 방식

원화 기반의 연속 메쉬 변형을 우선 사용한다. 감은 눈의 선·웃는 눈의 곡선·둥근 입처럼 기존 그림을 늘이는 것만으로 만들기 어려운 모양은 **부위 단위 대체 레이어 세트**로 준비한다. 대체 세트는 사용자가 미리보기 후 적용하는 모양 자산이다. 원래 파츠와 원화는 보관한다.

눈 세트는 흰자·홍채·위/아래 눈꺼풀, 입 세트는 입안·위/아래 입술 등 필요한 독립 파츠로 구성한다. 한 이미지에 여러 독립 파츠를 합치지 않는다. 원화 마스크의 비겹침 분할과 별도의 `fillMask` 계약은 유지한다. 대체 세트는 별도 모양 자산으로 저장하며 원본 `parts[].mask`를 표정 전환 때마다 다시 쓰지 않는다.

각 부위는 한 시점에 하나의 모양 세트가 소유한다. 원래 눈과 대체 눈이 중복으로 남지 않도록 해당 부위의 원래 레이어를 숨기고 세트를 표시한다. 깜빡임 전환에는 연속 변형과 클리핑을 우선 사용한다. 선화가 겹쳐 보이는 무조건적인 알파 교차 전환은 기본 해법으로 삼지 않는다. 감은 눈에서는 흰자·홍채를 함께 가리고, 얼굴 아래에 남은 원래 눈/입 픽셀도 점검한다.

단일 이미지의 숨은 그림을 정확히 복원한다고 약속하지 않는다. 기본 원화 유지와, 사용자가 선택한 다른 모양으로 바꾸는 동작을 명확히 구분한다. 참고 PSD는 구조·평가 자료이며 배포용 모양 자산으로 자동 전용하지 않는다.

## 7. 저장 구조와 공통 재생기

다음은 신규 설계 계약이며 현재 구현 완료를 뜻하지 않는다.

| 데이터 | 내용 |
| --- | --- |
| `RigProfile` | 기준점, 부위별 조정값, 좌우 연결 여부, 회전·시선·물리 강도와 안전 범위, 프로파일 버전 |
| `ShapePreset` | 고유 ID, 눈 L/R 또는 입 대상, 모양/레시피 버전, 곡선 핸들·변형 설정, 필요 시 대체 파츠 자산 참조 |
| `ExpressionPreset` | 고유 ID·이름, 선택한 눈/입 모양, 기존 `Parameters`의 부분 값, 강도·전환 시간 |
| `PlaybackSettings` | 기본 표정, 자동 깜빡임·호흡·유휴 움직임 설정, 앱 포커스 단축키 |
| `Project` v3 | 기존 원화·파츠·마스크와 위 데이터, ZIP 내부 모양 PNG/마스크. 썸네일은 재생성 가능한 캐시 |

`rig-profile.json` 등 새 파일명을 추가하더라도 Cubism 공식 가져오기 형식으로 표기하지 않는다. 모델 파일·로컬 절대경로에 의존하지 않고 프로젝트에 필요한 모양 자산을 포함한다. 레시피 갱신으로 기존 캐릭터가 바뀌지 않도록 선택한 레시피 버전과 조정값 또는 생성 결과를 보관한다.

재생은 `프로젝트 + 표정 + 테스트/입력 상태 + 시간 → 평가된 포즈·활성 모양·클리핑 상태 → 렌더링`의 한 경로로 구성한다. 현재 `Viewport.tsx` 내부의 사인파 모션·눈 깜빡임·물리는 평가기로 분리한다. 썸네일·편집 미리보기·재생 화면·PNG 출력이 같은 평가기와 렌더 함수를 사용한다.

입력 우선순위는 부위별로 고정한다. 기본값 → 표정 → 사용자가 해당 부위에서 조정 중인 값 → 허용된 자동 동작 → 범위 제한 → 물리/렌더 순서다. 감은 눈·윙크 표정에서는 자동 깜빡임이 눈을 다시 열지 않고, 자동 입 움직임은 MVP에서 끈다. 표정 강도는 REST에서의 보간이며 프레임마다 누적하지 않는다. 정지·탐색·재열기 시 물리 상태를 초기화한다.

기존 Rust/TypeScript 메쉬 변형 수식과 새 부위 조정의 좌표·축·피벗은 함께 유지한다. 현재 2축 입 개폐/형태만으로 모든 모양을 표현한다고 가정하지 않는다. 필요한 모양 설정은 부위 프로파일에 추가하고, 공용 변형 입력에 영향을 주면 Rust/TS 계약과 동등성 검사를 함께 확장한다.

## 8. 구현 순서와 출시 판단

주차 대신 완료 조건에 따라 진행한다.

1. **기반 품질 확인**: 현재 수정 상태 재검증, 원화 기본 상태·수동 수정 보존·일반형/SD형 소규모 원화 자료 확보.
2. **저장/재생 계약**: v3와 하위 버전 읽기, 공통 평가기·렌더러, 기존 움직임 결과 유지.
3. **눈·입 모양**: 원화 유지 모양을 기준으로 최소 세트 제작, 부위별 핸들·교체·클리핑·저장.
4. **표정/움직임 조정**: 표정 카드, 조합·강도·안전 범위, 자동 동작 우선순위, 실행 취소.
5. **앱 안에서 완결**: 새 기본 화면, 재생 화면, PNG 출력, 저장/재열기, Windows 네이티브 검증.

최소 평가 자료는 참고 PSD의 합성 이미지와 별도 일반형 2장·SD형 3장으로 총 6장 이상 확보한다. 이는 초기 회귀 자료 규모이며 일반화 성능을 뜻하지 않는다. 눈·입 확대, 원본/기본, 각 모양, 표정 전환, 작은 고개 회전 조합을 같은 조건으로 기록한다.

제품 검수는 자동 분석 성공률과 보정 후 완성률을 구분한다. 목표는 신규 사용자 3명이 각자 지원 범위의 캐릭터로 15분 내 기본 위치 보정·눈/입 선택·표정 1개 저장·재열기·재생을 완료하는 것이다. 수치는 출시 목표이며 측정 결과가 아니다. 지원이 필요했던 단계와 시간을 함께 남긴다.

## 9. 다음 확장과 이번 제외 범위

앱 내 재생이 안정화된 뒤 별도 작업으로 **Windows 투명 재생 창과 OBS 창 캡처 확인**, **마이크 음량에 따른 입 개폐**, **웹캠 추적**을 순서대로 검토한다. 음량 기반 개폐를 A/I/U/E/O 음소 인식으로 표시하지 않는다. 현재 프레임 PNG 이후 동영상/GIF 출력은 인코더·프레임 합성 검증을 별도로 계획한다.

이번에는 범용 메쉬/키폼/타임라인 편집기, 전신 리깅, 의상 물리, 자동 음소 인식, 직접 CMO3/MOC3 생성, 외부 방송 앱 연동, 자체 런타임 배포 SDK를 만들지 않는다. Cubism으로의 선택 인계는 유지하지만 제품 완료 조건으로 요구하지 않는다.

## 10. 검증 상태

이번 문서 작성 중 기존 TypeScript 검사 27개, Rust 라이브러리 검사 26개와 `npm run build`가 통과했다. 모델·자료가 없으면 조기 반환하는 검사가 있으므로 전체 추론 정합성 통과를 뜻하지 않는다. 소스에서 추가된 수정 경로를 확인했지만 새 표정 기능은 아직 구현하지 않았다. 일반형/SD형 실제 GUI 품질·사용성·투명 창·Cubism 가져오기를 통과한 것으로 간주하지 않는다.
