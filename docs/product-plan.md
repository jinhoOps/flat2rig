# flat2rig 제품 전환 계획

작성일: 2026-11-15 · 개정일: 2026-11-16 (`v0.2.0-3` 4단계 하이브리드 실루엣 적층 이후 아키텍처 기준 반영) · 2026-11-18 (숨은 영역 품질 모델: 이음새 계약·노출 맵·영역 유형별 합성·원본감 평가 추가, [검수 기록](template-architecture-review.md)).

이 문서는 제품 목표와 MVP 범위의 기준이다. 기존 `mvp-spec.md`와 `implementation-plan.md`의 Cubism 인계 중심 목표를 대체한다. 구현 순서와 개발자에게 전달할 지시는 [development-tasks.md](development-tasks.md)를 따른다.

## 1. 바뀐 목표와 핵심 설계 원칙

Cubism 작업이 부담스러운 사용자가 일러스트 한 장에서 시작해, 앱 안에서 눈·입 모양과 표정을 선택하고 움직임을 조정한 캐릭터를 저장·재생하게 한다. 파츠와 메쉬를 직접 제작하는 과정 대신 미리 정의한 모델·소체 구조에 자신의 일러스트를 입히고, 필요한 부분만 수동 보정해 완성하는 과정이 기본 사용법이다.

> **핵심 설계 원칙 (2026-11-16 재정립)**:
> 원본 일러스트를 훼손하지 않는 것 자체가 목적이 아니라, **원본의 시각적 정체성을 유지하면서 보이지 않는 영역까지 완성하는 것**이 목적이다. 원화는 정지 상태의 기준이며, 최종 파츠는 원화보다 더 넓은 영역을 가져야 한다. 각 파츠는 완전한 형태와 텍스처를 가지고, 겹침·클리핑·변형을 통해 자연스럽게 움직여야 한다.

주요 완료 지점은 **앱에서 캐릭터를 완성하고 다시 열어 재생하는 것**이다. PSD와 Cubism 인계 자료는 더 정교하게 작업하려는 사용자를 위한 선택 출력으로 유지한다. Cubism을 설치하거나 조작해야 기본 사용을 완료할 수 있는 흐름은 제거한다.

### 파이프라인 구조

```text
원본 일러스트
  └─▶ 랜드마크 · 색상 · 경계 · 파츠 추출 (ONNX + 4단계 실루엣 적층)
        ├─▶ 원본 가시 파츠 (`mask`: 관측된 텍스처, 정지 기준)
        └─▶ LD / SD 소체 피팅 (숨은 영역의 전체 형상)
              └─▶ 이음새 계약(SeamGraph) · 노출 맵(ExposureMap)  ← 변형 함수의 포즈 포락선 샘플링
                    └─▶ 영역 유형별 텍스처 확장 (flat/cel 팔레트 필드 · line 선화 연장 · texture 예시 패치 · semantic 자산/수동)
                          └─▶ 완성된 개별 파츠 (`mask` + `fillMask` + `texture` + `mesh` + `clipTarget` + `compositeOrder`)
                                └─▶ ArtMesh · Deformer · Z-order · Clipping ──▶ XYZ 움직임과 표정 변화
                                      └─▶ 원본감 평가 (정답 PSD 비교 · 자기 지도 홀드아웃 · 노출 밴드 지표)
```

사용자가 말한 “Cubism 미니 포터블”은 기능 범위를 설명하는 내부 비유로 해석한다. 제품명은 flat2rig를 유지하며, 독립적인 편집·재생 기능을 개발한다. 설치 없는 Windows 배포는 별도 배포 검증 항목이다.

## 2.5. 숨은 영역 확장 · 부위별 겹침 · 파츠 데이터 계약

### 부위별 숨은 영역 생성과 겹침 처리

단순히 `fillMask`를 `2~4px` 확장하는 것만으로는 모션 시 틈이 생긴다. `2~4px`는 최소 시작값으로만 두고, **원화 해상도(`HeadFrame.hh`)와 각 파츠의 최대 변형량(`core.rs`/`engine.ts`)**을 고려해 부위별 겹침 여유분을 다르게 산정한다.

| 부위 | 숨은 영역 생성 | 겹침 처리 |
| --- | --- | --- |
| 얼굴·앞머리 | 이마와 양옆 두피 확장 | 앞머리가 얼굴 위를 덮음 |
| 턱·목 | 턱 아래 목 전체 연결 | 얼굴이 목 위를 충분히 덮음 |
| 눈·눈꺼풀 | 흰자·홍채의 보이지 않는 부분 확장 | 눈꺼풀·흰자 클리핑 (`eye*_iris → eye*_white`) |
| 옆머리·얼굴 | 얼굴 뒤·모자/앞머리 아래 머리카락 뿌리 생성 | 앞·옆·뒷머리 Z-order + 모션 비례 언더랩 |
| 의상·목 | 옷깃 뒤의 목과 몸통·손 뒤 의상 채움 | 옷깃·소매 아래 숨은 영역 연결 |

- **경계 후광 방지 및 국소 색상 필드**: 원화 최외곽 경계의 밝은/어두운 반투명 픽셀을 그대로 확장하면 흰 테두리나 선화 번짐이 생긴다. 샘플링은 외곽을 침식한 안쪽의 깨끗한 색상에서 시작하고, 명암 변화가 있는 부위(이마·턱 아래·머리 음영)는 단일 평균색 대신 국소 색상 필드로 연장한다.
- **추정 영역 관리 및 수동 보정**: 원본에 없는 복잡한 무늬나 선화는 비생성형 샘플링만으로 정확히 복원할 수 없다. 숨은 영역(`fillMask`)은 추정 영역으로 구분해 오버레이로 확인하고, 사용자가 정지 원화(`mask`)를 훼손하지 않고 `fillMask`와 숨은 텍스처를 직접 수동 보정하거나 PNG로 교체할 수 있어야 한다.

### 파츠 3종 데이터와 런타임 계약

개념 모델의 `RigPart`는 완전히 새 자료구조로 갈아엎지 않고 기존 `Part`([src/types.ts](file:///C:/Users/kjh/orca/flat2rig/src/types.ts))와 `RigProfile`을 그대로 확장해 대응한다.

```ts
// 개념 계약 (RigPart) ↔ 현재 Part / RigProfile 매핑
// visibleMask -> Part.mask                   (원본에서 실제 보이는 비겹침 영역)
// hiddenMask  -> Part.fillMask               (움직일 때 필요해 생성한 숨은 영역, masks/<id>.fill.bin)
// texture     -> Part.texture                (원본과 확장 영역을 포함한 최종 RGBA)
// mesh        -> effectiveMask               (`mask | fillMask` 전체를 덮는 Delaunay 메쉬)
// clipTarget  -> RigProfile.clippingTargets  (부모 파츠 및 클리핑 대상)
// zIndex      -> Part.compositeOrder         (합성 순서)
```

## 2.6. 숨은 영역 품질 모델 (2026-11-18 보완)

"숨은 영역까지 원본처럼"은 `fillMask`를 넓히고 매끄럽게 칠하는 것만으로는 달성할 수 없다. 현재 합성기(`build_color_field`, 조화 보간)는 틈을 막는 데 충분하지만, 셀 채색의 단단한 그림자 경계·선화·질감을 재현하지 못한다. 근거와 코드 검수는 [template-architecture-review.md](template-architecture-review.md)의 2026-11-18 항목에 있다. 다음 네 가지를 설계 기준으로 추가한다.

1. **품질 기준 영역은 노출 영역이다.** 숨은 영역 전체가 아니라, 허용 모션 범위(파라미터 정의 범위 전체, 축소 금지)에서 실제로 드러나는 밴드(`ExposureMap`)를 품질 목표 영역으로 삼는다. 노출되지 않는 숨은 영역은 틈 방지와 PSD 인계용 연속성만 만족하면 된다.
2. **노출을 줄이는 것이 합성보다 먼저다.** 이음새 양쪽 파츠의 변형장을 결합해 이음새의 *상대 변위*를 줄인다(머리카락 뿌리↔두피, 목 상단↔머리, 옷깃↔몸통). 최대 각도는 그대로 둔다. 필요 여유분은 손으로 옮긴 상수가 아니라 `deform`의 포즈 포락선 수치 샘플링으로 이음새 계약(`SeamGraph`)마다 산출한다.
3. **영역 유형마다 합성기가 다르다.** 숨은 영역을 `flat/cel`(팔레트 스냅 + 그림자 경계 레벨셋 연장), `line`(선화 분리·접선 연장·숨은 윤곽선 생성), `texture`(같은 파츠 내측의 예시 패치 합성), `semantic`(모양 자산·사용자 입력)으로 분류하고 `fillKind`에 기록한다. 생성형 인페인팅은 선택 연구 항목이며 선행 조건이 아니다.
4. **원본감은 측정한다.** 참고 PSD의 실제 숨은 레이어와 비교하는 정답 평가와, 보이는 이음새 밴드를 가렸다가 합성해 비교하는 자기 지도 홀드아웃 평가로 노출 밴드의 색차(ΔE2000)·팔레트 일치·이음새 그래디언트 불연속·선화 끊김을 수치화한다. 임계값은 기준선 측정 뒤에 정한다.

목표의 정직한 정의: 단일 이미지에서 가려진 원래 그림을 확정할 수는 없다. 제품 목표는 **"드러나는 밴드가 원화와 같은 화풍 규칙을 따라 원화와 구분되지 않는 것"**이며, 노출 깊이가 커서 비생성형으로 보장할 수 없는 영역은 `semantic`/수동 영역으로 표시한다.

## 3. 대상과 입력 범위

- 대상: 파츠 분리와 키폼 제작을 처음부터 하기 어려운 일러스트 작가·개인 캐릭터 사용자.
- 우선 입력: 한 명의 정면 또는 정면에 가까운 일반형/SD형 흉상 PNG/JPEG. 작업 해상도 긴 변 최대 2,048px를 유지한다.
- 자동 결과는 수정 가능한 초안이다. 실패하면 눈·입·턱 위치와 얼굴 영역을 직접 맞춘 뒤 진행할 수 있어야 한다.
- 원화에 없는 닫힌 눈·입안·다른 입모양은 추정 결과로 표시하고, 적용 전에 현재 캐릭터로 미리 보여준다.
- 초기에는 큰 고개 회전보다 정면의 표정·눈·입과 작은 움직임을 우선한다. 전신·측면·손/의상 관절은 별도 범위다.

## 4. 기본 사용 흐름과 화면

1. **준비**: 이미지 드래그 앤 드롭 → 자동 분석 → 일반형/SD형 확인 → 얼굴·눈·입 위치 보정. 원본/기본 합성 비교를 제공한다.
2. **표정**: 원화로 만든 썸네일에서 눈 모양·입 모양·표정을 고른다. 기본 표정으로 즉시 복귀할 수 있다.
3. **조정**: 선택한 눈·입의 위치·크기·입꼬리·눈꺼풀 곡률과 동작 강도를 조정한다. 파츠·메쉬·모델 설정은 고급 패널로 이동한다.
4. **재생**: 수동 표정 전환과 자동 눈 깜빡임·호흡·작은 고개/머리 움직임을 확인한다. 자동 움직임은 부위별로 끌 수 있다.
5. **저장/출력**: `.flat2rig`로 저장하고 재열기, 현재 프레임 투명 PNG 출력. 선택적으로 PSD/기존 인계 패키지를 내보낸다.

3단 작업 공간과 `DESIGN.md`의 밝은 아크릴·코발트·그라파이트 색을 유지한다. 좌측은 현재 단계에 따라 파츠 또는 모양/표정 목록, 중앙은 캐릭터, 우측은 선택한 항목의 조정값을 표시한다. 기본 화면에 전체 Live2D 파라미터 목록을 펼치지 않는다. 사용자에게 보이는 용어는 `눈 모양`, `입 모양`, `표정`, `움직임`, `원래대로`처럼 동작 중심으로 쓴다.

| 기능 | 제공할 내용 | 완료 기준 |
| --- | --- | --- |
| 기본 상태 · 숨은 영역 | 원화 정체성 유지, 숨은 영역(`fillMask`) 확장, 원본/결과 전환, 노출 영역 표시 | 정지 포즈 색상·실루엣 자연스러움 통과, 5대 모션·이음새 검증 통과, 노출 밴드 원본감 지표가 기준선 대비 개선되고 기록됨 |
| 눈 모양 | 원래 눈, 반쯤 감김, 감은 눈, 웃는 눈 | 좌우 독립 적용, 양쪽 연결 편집, 감김·시선·눈웃음 조합에서 흰자·홍채가 새지 않고 이중 선화 없음 |
| 입 모양 | 원래 입, 닫힌 입, A/I/U/E/O | 벌어짐 외에 폭·둥글기·입꼬리·입안 노출이 구분됨. 정면 모양 프리셋이며 음성 인식은 아님 |
| 표정 | 기본, 미소, 기쁨, 화남, 슬픔, 놀람, 좌/우 윙크 | 조합을 저장·복제·이름 변경·초기화. 윙크의 L/R은 캐릭터 기준이고 UI에 위치를 함께 표시 |
| 세부 조정 · 추정 보정 | 눈/입 기준점·곡선 핸들, 추정 `fillMask`/숨은 텍스처 직접 보정 | 수동 버텍스·가중치 작업 없이 조정, 원화 `mask`를 훼손하지 않고 추정 영역 보정, undo/redo |
| 움직임 | 고개 이동/기울임, 시선, 깜빡임, 호흡, 머리 흔들림 | 각도 축소로 결함을 덮지 않고 겹침 여유분·클리핑으로 틈·후광 방지, 안전 범위·강도 저장 |
| 로컬 재생 | 앱 내 전용 재생 화면, 클릭/앱 포커스 단축키 표정 전환 | 편집 화면과 동일한 프레임 결과, 저장된 프로젝트를 모델 추론 없이 재생 |

기본 프리셋 개수만 채워 완료 처리하지 않는다. 예를 들어 U와 O가 동일한 확대 이미지라면 미완료다. 원화 특성상 생성에 실패한 모양이나 복원 한계가 큰 복잡 무늬는 `수정 필요`·추정 영역으로 표시하고 `fillMask`/텍스처 수동 보정 또는 PNG 교체로 해결하게 한다.

## 6. 눈·입 생성과 전환 방식

원화 기반의 연속 메쉬 변형을 우선 사용한다. 감은 눈의 선·웃는 눈의 곡선·둥근 입처럼 기존 그림을 늘이는 것만으로 만들기 어려운 모양은 **부위 단위 대체 레이어 세트**로 준비한다. 대체 세트는 사용자가 미리보기 후 적용하는 모양 자산이다. 원래 파츠와 원화는 보관한다.

눈 세트는 흰자·홍채·위/아래 눈꺼풀, 입 세트는 입안·위/아래 입술 등 필요한 독립 파츠로 구성한다. 한 이미지에 여러 독립 파츠를 합치지 않는다. 원화 마스크의 비겹침 분할(`mask`)과 별도의 숨은 영역(`fillMask`) 계약은 유지하며, 메쉬(`effectiveMask`)와 텍스처는 두 영역을 모두 포괄한다. 대체 세트는 별도 모양 자산으로 저장하며 원본 `parts[].mask`를 표정 전환 때마다 다시 쓰지 않는다.

각 부위는 한 시점에 하나의 모양 세트가 소유한다. 원래 눈과 대체 눈이 중복으로 남지 않도록 해당 부위의 원래 레이어를 숨기고 세트를 표시한다. 깜빡임 전환에는 연속 변형과 클리핑(`eye*_iris → eye*_white`)을 우선 사용한다. 선화가 겹쳐 보이는 무조건적인 알파 교차 전환은 기본 해법으로 삼지 않는다. 감은 눈에서는 흰자·홍채가 바깥으로 새지 않도록 완전히 밀폐하고, `face` 아래에 원래 눈/입 잔상 선화가 남지 않도록 내측 피부 필드로 덮는다.

복잡 무늬·가려진 디테일을 생성형 모델 없이 100% 정확히 복원한다고 약속하지는 않지만, 움직임에 필요한 숨은 영역(`fillMask`)과 국소 색상 필드는 적극적으로 생성하고 추정 영역으로 관리해 사용자가 수동 보정할 수 있게 한다. 참고 PSD는 구조·평가 자료이며 배포용 모양 자산으로 자동 전용하지 않는다.

## 7. 저장 구조와 공통 재생기

아래 저장·평가 계약(`RigProfile`, `ShapePreset`, `ExpressionPreset`, `PlaybackSettings`, `Project` v3)은 `v0.2.0-3` 기준 `src/types.ts`, `src/io.ts`, `src/rig/evaluate.ts`, `src/rig/render.ts`에 구현되어 있으며, 후속 작업에서는 **모션 비례 `fillMask` · 추정 영역 수동 보정 메타 · 5대 모션 검증 결과**를 보강한다.

| 데이터 | 내용 |
| --- | --- |
| `RigProfile` | 기준점, 부위별 조정값, 좌우 연결 여부, `clippingTargets`, 회전·시선·물리 강도와 안전 범위, 프로파일 버전 |
| `ShapePreset` | 고유 ID, 눈 L/R 또는 입 대상, 모양/레시피 버전, 곡선 핸들·변형 설정, 필요 시 대체 파츠 자산 참조 |
| `ExpressionPreset` | 고유 ID·이름, 선택한 눈/입 모양, 기존 `Parameters`의 부분 값, 강도·전환 시간 |
| `PlaybackSettings` | 기본 표정, 자동 깜빡임·호흡·유휴 움직임 설정, 앱 포커스 단축키 |
| `Project` v3 | 기존 원화·파츠·마스크(`masks/<id>.bin`, `masks/<id>.fill.bin`)와 위 데이터, ZIP 내부 모양 PNG/마스크. 썸네일은 재생성 가능한 캐시 |

`rig-profile.json` 등 새 파일명을 추가하더라도 Cubism 공식 가져오기 형식으로 표기하지 않는다. 모델 파일·로컬 절대경로에 의존하지 않고 프로젝트에 필요한 모양 자산을 포함한다. 레시피 갱신으로 기존 캐릭터가 바뀌지 않도록 선택한 레시피 버전과 조정값 또는 생성 결과를 보관한다.

재생은 `프로젝트 + 표정 + 테스트/입력 상태 + 시간 → 평가된 포즈·활성 모양·클리핑 상태 → 렌더링`의 한 경로(`evaluate.ts` → `render.ts` / `glRenderer.ts`)로 구성한다. 썸네일·편집 미리보기·재생 화면·PNG 출력이 같은 평가기와 렌더 함수를 사용한다.

입력 우선순위는 부위별로 고정한다. 기본값 → 표정 → 사용자가 해당 부위에서 조정 중인 값 → 허용된 자동 동작 → 범위 제한 → 물리/렌더 순서다. 감은 눈·윙크 표정에서는 자동 깜빡임이 눈을 다시 열지 않고, 자동 입 움직임은 기본 재생에서 끈다. 표정 강도는 REST에서의 보간이며 프레임마다 누적하지 않는다. 정지·탐색·재열기 시 물리 상태를 초기화한다.

기존 Rust/TypeScript 메쉬 변형 수식(`core.rs` ↔ `engine.ts`)과 새 부위 조정의 좌표·축·피벗(`HeadFrame`)은 함께 유지한다. 필요한 모양 설정이나 모션 계약을 바꾸면 Rust/TS 동등성 검사를 함께 확장한다.

8. **모션·이음새·원본감 검증 게이트 (`T12`)**: XYZ 움직임 각도를 줄이는 것으로 문제를 가리지 않고, **각 파츠의 독립 메쉬와 텍스처가 움직이는 상태에서** 아래 5가지 결함 기준과 6번째 원본감 지표를 검증한다.
9. **(조건부) 질감 예시 합성 / 생성형 인페인팅 연구 (`T16`)**: T14 수치가 `texture`/`semantic` 영역에서 한계를 보일 때만 착수한다.
   1. 원본과 동일한 기본 포즈에서 색상·실루엣이 자연스러운가?
   2. 얼굴과 목을 반대 방향으로 조금씩 움직여도 틈이 없는가?
   3. 눈을 감을 때 안쪽 홍채·흰자가 새어 나오지 않는가?
   4. 머리카락을 움직일 때 피부나 배경의 빈 공간이 노출되지 않는가?
   5. 파츠가 겹치는 곳에서 선화가 이중으로 보이거나 흰 테두리가 나타나지 않는가?
   6. (원본감) 허용 모션 범위에서 드러나는 노출 밴드가 원화와 같은 팔레트·그림자 경계·선화 연속성을 갖는가? (T14 지표로 수치 기록. 결함 0만으로 통과 처리하지 않음)

최소 평가 자료는 참고 PSD의 합성 이미지와 별도 일반형 2장·SD형 3장으로 총 6장 이상 확보한다. 이는 초기 회귀 자료 규모이며 일반화 성능을 뜻하지 않는다. 눈·입 확대, 원본/기본, 각 모양, 표정 전환, 고개·목 반대 이동 및 머리카락 흔들림 조합을 같은 조건으로 기록한다.

제품 검수는 자동 분석 성공률과 보정 후 완성률을 구분한다. 목표는 신규 사용자 3명이 각자 지원 범위의 캐릭터로 15분 내 기본 위치 보정·눈/입 선택·표정 1개 저장·재열기·재생을 완료하는 것이다. 수치는 출시 목표이며 측정 결과가 아니다. 지원이 필요했던 단계와 시간을 함께 남긴다.

## 9. 다음 확장과 이번 제외 범위

앱 내 재생이 안정화된 뒤 별도 작업으로 **Windows 투명 재생 창과 OBS 창 캡처 확인**, **마이크 음량에 따른 입 개폐**, **웹캠 추적**을 순서대로 검토한다. 음량 기반 개폐를 A/I/U/E/O 음소 인식으로 표시하지 않는다. 현재 프레임 PNG 이후 동영상/GIF 출력은 인코더·프레임 합성 검증을 별도로 계획한다.

이번에는 범용 메쉬/키폼/타임라인 편집기, 전신 리깅, 의상 물리, 자동 음소 인식, 직접 CMO3/MOC3 생성, 외부 방송 앱 연동, 자체 런타임 배포 SDK를 만들지 않는다. Cubism으로의 선택 인계는 유지하지만 제품 완료 조건으로 요구하지 않는다.

## 10. 현재 검증 상태 요약

상세 실행 수치는 [validation.md](validation.md)를 기준으로 한다. `v0.2.0-3` 기준 TypeScript(`tsc --noEmit`), Vitest(38/38), Cargo clippy(0건), Cargo lib 테스트(30/30) 및 `Himikan`/`Rritteang`/`Sutteang` WebView2 E2E가 통과했으나, Rritteang 턱·안경 교차 미세 이음새와 Sutteang 목 얼룩·슬픔 눈 외곽 이음새, 그리고 T7 외부 원화 6장·신규 사용자 테스트·클린 PC `.msi` 실행·실제 Cubism 가져오기·`2048px` 60초 측정은 미완료/미검증 상태다. T8은 1차 구현(`79610ec`)만 반영되었고 Windows 실측·모션 검증은 기록되지 않았다(`미검증`). T9–T16은 설계·계획 단계이며 아직 구현·검증되지 않았다. 숨은 영역 원본감 지표는 아직 측정 방법(T14)조차 구현되지 않았다.
